# Apps-slides-server-services Specification

> Generated by openlore v1.0.0 on 2026-06-22 23:25

## Purpose

Manages the full lifecycle of slide feedback: reading, creating, and resolving feedback markers
embedded directly in slide source files (JSX comments in code slides, HTML comments in HTML slides).
*(analyzed in 2 chunks)*

## Requirements

> `apps\slides\server\services\slide-feedback.ts`

### Requirement: List

> Implementation: `*` in `apps\slides\shared\api.ts` · confidence: heuristic

The system SHALL reads all feedback markers from a presentation's slides. for code slides, parses jsx source files; for html slides, parses the stored html. optionally filters to a single slide.

#### Scenario: ListAllFeedbackForAPresentation
- **GIVEN** A valid presentationId with multiple slides containing feedback markers
- **WHEN** list is called with only presentationId
- **THEN** All feedback entries across all slides are returned

#### Scenario: ListFeedbackForASpecificSlide
- **GIVEN** A valid presentationId and slideId
- **WHEN** list is called with both presentationId and slideId
- **THEN** Only feedback entries for that slide are returned

#### Scenario: ListFeedbackForCodeSlide
- **GIVEN** A code slide with a valid code_id whose source file contains JSX feedback markers
- **WHEN** list is called
- **THEN** Feedback markers are parsed from the TSX source file and returned

#### Scenario: ListFeedbackForHTMLSlide
- **GIVEN** An HTML slide with embedded HTML feedback markers
- **WHEN** list is called
- **THEN** Feedback markers are parsed from the slide HTML and returned

#### Scenario: ListFeedbackForSlideWithNoCodeId
- **GIVEN** A code slide missing code_id
- **WHEN** list is called
- **THEN** An empty array is returned

#### Scenario: PresentationNotFound
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A presentationId that does not exist
- **WHEN** list is called
- **THEN** AppError 404 is thrown

### Requirement: Create

> Implementation: `createSlideFeedbackActions` in `apps\slides\actions\slide-feedback.ts` · confidence: heuristic

The system SHALL creates a new feedback record with a generated id and embeds it as a marker into the slide's source: jsx comment for code slides, html comment for html slides.

#### Scenario: CreateFeedbackOnCodeSlide
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A valid code slide with a resolvable TSX source file
- **WHEN** create is called with feedback text
- **THEN** Feedback record created, JSX marker inserted into the source file, feedback returned

#### Scenario: CreateFeedbackOnHTMLSlide
<!-- openlore-test: tags=smoke (auto) -->

### Requirement: Resolve

> Implementation: `*` in `apps\slides\shared\api.ts` · confidence: heuristic

The system SHALL marks an existing feedback item as resolved by replacing its embedded source marker with an updated resolved record. persists back to source file (code slides) or slide html (html slides).

#### Scenario: ResolveFeedbackOnCodeSlide
- **GIVEN** A code slide with an existing open feedback marker in its TSX source
- **WHEN** resolve is called with the matching feedbackId
- **THEN** Marker replaced with resolved state in source file, resolved feedback returned

#### Scenario: ResolveFeedbackOnHTMLSlide
- **GIVEN** An HTML slide with an existing open feedback marker
- **WHEN** resolve is called with the matching feedbackId
- **THEN** Marker replaced with resolved state in slide HTML, slide updated in repository, resolved feedback
returned
